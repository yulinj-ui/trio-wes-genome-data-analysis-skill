# 家系 Trio WES 病例分析标准流程(SOP)

> 基于首个家系病例的实战总结,含全部踩坑经验。下次给出新病例的临床信息+基因组数据时,按本流程走。

---

## 总览:六阶段流程

```
① 病例接收与HPO标准化 → ② 数据定位与身份核验 → ③ 数据完整性/质量核查
        ↓                                                    ↓
⑥ 候选变异排序+ACMG判读 ← ⑤ 表型-基因型比对 ← ④ 生信分析流程(比对→call→注释→筛选)
```

**关键原则**:①②③是"防错关卡",一步都不能省——本案例的多数教训都出在这几步被跳过或轻信默认假设上。

---

## 阶段① 病例接收与 HPO 表型标准化

### 输入
- 临床病历/超声报告(文字或截图)
- 既往检测报告(若有,如商业WES/CMA报告PDF)
- 家族史、孕产史(**尤其孕次胎次G/P、既往异常妊娠史——这是判断"是否复发"、"该套数据到底对应哪一胎"的关键上下文**)

### 必须执行
1. **提取标准化临床信息**,转换成 HPO 术语列表(建立 `phenotype_HPO.txt`,格式参考本案例模板)
2. **明确遗传背景假设**:是否怀疑复发(需要明确"复发"指的是哪几次妊娠)、AD/AR/XL何者优先、是否有近亲婚配、是否怀疑亲代生殖腺嵌合
3. **构建/复用候选基因 panel**(`panel_CAKUT_CHD.txt` 同类模板,按表型选择对应疾病谱基因清单)
4. ⚠️ **明确当前这批数据对应的是哪一次妊娠/哪个个体**——不要想当然。本案例的重大教训:文件夹名"某某**第一胎**数据"字面已经说明是第一胎,但因为默认假设成了"当前妊娠",导致前大半个会话的分析对象都搞错了。**这一步必须让用户明确确认,不能靠推断。**

### 输出
- `phenotype_HPO.txt`(HPO列表 + 原始超声/病历摘录)
- `panel_XXX.txt`(候选基因清单)
- 一句话确认:"本次分析的样本对应【第几胎/哪次检测/哪个送检编号】"

---

## 阶段② 数据定位与身份核验

### 必须执行
1. **确认数据存放路径**,若涉及大文件优先放外置盘(建议用外置 SSD,建立 `<外置盘>/genomics/{refs,work,results}` 结构,refs为多病例共享参考库;容器化运行时分别挂载为 /refs、/work、/results)
2. **样本身份核验(极重要,不能跳过)**:
   - 文件名/送检编号是否与病历/报告一致(交叉核对姓名、送检单位、送检日期、样本编号)
   - **若已有该个体的既往检测报告(哪怕是不同实验室/不同基因组版本),用报告里列出的具体变异位点做"指纹比对"**——这是本案例验证出的一个非常有效的方法:把报告里的变异(注意核对基因组版本,如实验室是GRCh37/hg19,需转换坐标)去比对自己流水线call出的VCF,基因型是否吻合。**这比单纯核对文件名可靠得多**,本案例中靠这个方法在12个变异中发现5个原报告与重新分析结果不一致的情况。
3. **确认家系关系与性别**:PED文件的父母子女关系是否正确;胎儿/先证者性别若未知,用chrX/chrY覆盖度比值判定(不要等到XL分析阶段才发现没做)

### 输出
- 确认后的样本-个体对应关系表
- (若有既往报告可比对)一份变异层面的身份核验结果
- `trio.ped`

---

## 阶段③ 数据完整性与质量核查

### 必须执行
1. MD5校验(若提供)
2. FASTQ基本信息:测序平台、读长、质量编码、双端/单端、数据量估算
3. **判定 WES vs WGS**:抽样比对+算外显子on-target占比(>50%=WES,<10%=WGS),决定后续磁盘方案与是否需要捕获区间BED
4. 比对后覆盖度QC(mosdepth):目标区平均深度、>10x/>20x占比是否达标(参考:商业实验室报告通常要求平均深度>100x、10x覆盖>98%、20x覆盖>95%,可作为自建流程的质控基准)
5. 三样本一致性检查:亲缘关系(可用变异层面的孟德尔一致率快速验证trio关系是否正确,而非仅信任文件命名)

### 输出
- 覆盖度/质量QC报告
- WES/WGS判定结论(决定`config.sh`的`ASSAY`和`CAPTURE_BED`)

---

## 阶段④ 生信分析流程

> 环境与参考库是**一次性投入、可跨病例复用**的部分;每个新病例只需改 `config.sh` 里的样本路径。

### 环境(一次性,已就绪则跳过)
- conda环境`trio`:bwa-mem2/samtools/bcftools/gatk4/snpEff+SnpSift(⚠️不用VEP,arm64段错误)/mosdepth/slivar/bedtools/fastp等
- **已知坑**(全部已在脚本里修复,新病例直接复用即可):
  - macOS系统bash 3.2不支持关联数组
  - conda激活脚本与`set -u`冲突,需`set +u; conda activate; set -u`包裹
  - samtools易被依赖关系拖回古董版0.1.19(卸载VEP相关perl包后重装`samtools>=1.20`)
  - **samtools 1.22+默认写CRAM 3.1,但GATK 4.6的htsjdk只认3.0**,`samtools view -C`必须显式加`--output-fmt-option version=3.0`
  - GATK known-sites旧桶`genomics-public-data`已403,正确桶是`gcp-public-data--broad-references`
  - dbNSFP(50GB学术版)单连接易断,需`curl -C - --retry`断点续传,可能需多次重试

### 参考库(一次性,已就绪则跳过)
- GRCh38基因组+bwa-mem2索引+dbSNP/Mills/1000G+CDS区间
- snpEff GRCh38.p14数据库 + ClinVar + slivar-gnomAD gnotate库 + (可选)dbNSFP

### 每病例流程
```
02 比对(fastp→bwa-mem2→标记重复→BQSR→CRAM,三样本)
03 联合call variant(HaplotypeCaller×N→联合定型→硬过滤→PED)
04 注释(snpEff+dbNSFP+ClinVar,_JAVA_OPTIONS加大堆内存避免OOM)
05 遗传模型筛选(AD/de novo · AR纯合 · AR复合杂合 · XL,按panel tier1优先)
```

## 阶段⑤ 表型-基因型比对

### 必须执行
1. **候选表按panel内/外分层**(tier1=panel命中优先看,tier2=全外显子兜底,避免遗漏panel外强候选)
2. 遗传模型逐一核对基因型模式是否符合孟德尔逻辑(⚠️**VCF样本列顺序是GATK按名字母排序,不一定是"父母子"顺序,务必先核实**)
3. **多等位基因位点(GT=0/2这类)需人工复核**,slivar等工具对multiallelic site的模型判断容易出错
4. 若涉及"跨多次妊娠复发"场景,**明确检查候选变异是否在所有相关个体/妊娠中都存在**——若只在其中一次妊娠出现,对"复发"这个问题的解释力就弱

### CNV补充扫描(可选但推荐,尤其标准SNV/indel流程"阴性"时)
- 小样本(单trio)不适合GATK gCNV/XHMM这类需要大参考panel的工具
- 可行方案:①复用已有mosdepth区间深度数据做手动比值扫描(零新依赖,几分钟出结果)②ExomeDepth(专为小队列设计)③CNVkit(flat reference模式)
- 手动比值扫描要点:**必须按每个样本自身的整体测序深度归一化后再比较**,不能直接比较原始深度(不同样本测序深度可能差异很大)

---

## 阶段⑥ 候选变异排序 + ACMG致病性判读

### 排序权重
表型匹配度 > 遗传模型契合度 > 群体频率 > 计算预测评分 > ClinVar已有记录

### ACMG判读执行方式
- 调用 `gene-variant-pathogenicity` 技能(本项目默认规则:见变异即评级,无需用户手动触发)
- **复杂/多个候选变异时,并行开子代理(Agent工具)逐个独立判读**,避免主对话上下文被单个变异的几十次检索淹没,也便于交叉核对
- **务必让每个判读独立执行 Step 0 蛋白改变外部验证**(VariantValidator)——本案例中流水线自动注释(snpEff)在两个基因上出现坐标/转录本错误,全靠这一步兜底揪出来

### ⚠️ 三个必须写入判读逻辑的关键陷阱(本案例验证过的真实教训)
1. **"两次妊娠都携带同一基因型"≠致病性证据**:若父母是固定杂合携带者,孟德尔分离律下每次妊娠本身就有~25%概率产生同样的复合杂合组合,与是否致病无关。这只能排除"单次随机事件",不能替代变异本身的功能证据。
2. **复合杂合的PM3不能循环论证**:两个变异都是未经独立验证的VUS时,不能互相"佐证"致病性——PM3的前提是配对变异本身已有独立证据。
3. **表型匹配度要诚实评估,不可强行关联**:即使基因确实和某类心脏/肾脏疾病相关,也要具体核实该基因已知疾病谱是否真的覆盖胎儿的**具体**异常(如TTN虽与心肌病相关,但其疾病谱从无肾脏受累报道,不能因为"心脏+其他系统"就往上套)。

### 输出
- 候选变异排序表 + 每个变异的完整ACMG报告
- 综合判断:何者最可能解释表型,并诚实说明证据强度(不要在证据不足时给出确定性结论)
- 下一步建议(家系验证、功能实验、CNV/结构变异补充分析、转诊建议等)

## 复用检查清单(每接手新病例时过一遍)

- [ ] 已让用户明确书面确认:这批数据对应的是哪次妊娠/哪个个体?
- [ ] 已提取并确认HPO表型列表?
- [ ] 已确认数据存放路径,大文件是否需要外置盘?
- [ ] 若有既往检测报告,已做变异层面的身份核验?
- [ ] 已判定WES/WGS,配置正确的CAPTURE_BED?
- [ ] 已判定胎儿/先证者性别(chrX/Y比值)?
- [ ] 环境与参考库是否可直接复用(同GRCh38、同bwa-mem2)?
- [ ] `config.sh`样本路径已更新为新病例?
- [ ] 遗传模型筛选后,tier1(panel内)候选是否已优先审查?
- [ ] 每个候选变异ACMG判读是否都独立走了Step 0外部验证?
- [ ] 是否涉及"复发"场景?若是,是否已检查候选变异在所有相关个体中的一致性,并避免把"重复出现"误当作"致病性证据"?

## ⛔ 静默失效防线（2026-08-07 固化，新病例必跑）

本流水线的失败几乎都不是崩溃，而是「退出码 0、文件照产、格式完好，但内容是空的或来自上一个病例」。
2026-08-06 某病例一次踩到三个（00b 取错 mosdepth 列、02b 亲缘门没跑却报完成、config 无条件赋值
吞掉 PANEL_FILE 传参导致误用上一例 panel）。因此在流程首尾各加一道防线：

| 时机 | 脚本 | 作用 |
|---|---|---|
| **开跑前（第一个跑）** | `00a_preflight.sh` | 打印本次病例配置全貌并断言：病例隔离、结果目录残留检测、fastq 六件套、**PANEL_SCOPE 声明 vs 实际**、JDK、参考资产、内存、磁盘 |
| **出报告前（必跑）** | `98_sanity_check.sh` | **量级断言**：样本身份与 VCF 列顺序、变异总数、亲缘门产物、注释链各环非零、候选表量级、de novo 数 |

新增 config 变量（换病例必改）：
- `PANEL_SCOPE` = `allgenes`（全外显子不分层）或 `panel`（表型定向 panel）
- `PANEL_RATIONALE` = 一句话写明选此范围的依据

取消 panel 分层时，用 `05a_make_allgenes_panel.sh` 从**本病例**的 annot VCF 现场生成全基因清单，
**禁止跨病例复用**（复用会漏基因且不报错）。

**推荐运行顺序**

- **trio（三样本，FAMILY_MODE=trio）**：
  `00a → 00b → 02×3 → 02b → 03 → 03b → 04 → 05a → 05 → 98 → 99`
- **quad（四样本：父+母+两个子代，FAMILY_MODE=quad）** —— 用于**复发病例**，做「两子代共有而父母不共有」的交集分析：
  `00a → 00b → 02×4(含 fetus1) → 02bq → 02c → 03q → 03b → 04 → 05a → 05 → 05q → 98 → 99`

  quad 与 trio 的差异：`02bq_qc_quad.sh`（四样本 QC，MCC 对两个子代各做一次）；
  `02c_king_kinship.sh`（KING-robust 亲缘仲裁，somalier 误报时的独立判据）；
  `03q_call_quad.sh`（HC×4 并行，产出 quad VCF **并由它抽出 trio VCF** 喂既有 03b/04/05 链，注释只跑一遍）；
  `05q_quad_shared.sh`（六种交集模型 + 表型优先反向搜索 + 3-C 夫妇共同携带扫描）。
  config 需填 `FAMILY_MODE=quad` 与 `ID_FETUS1` / `FQ_FETUS1_R1/R2` / `SEX_FETUS1`。
  ⚠️ 样本命名须保证字母序 = 先证者 < 母 < 父 < 第二子代（P1_/P2_/P3_/P4_）。
  详见 `prenatal-trio-genome-analysis/references/pipeline-runbook.md` 的「四人家系（quad）分析流程」节。
